### Important

**1. Safety broadcasts can be duplicated downstream when a plugin passes MIDI through.**
`src/BypassableInstance.cpp:242-249` adds a safety broadcast (AllNotesOff / AllSoundOff / ResetAllControllers) to BOTH `tempMidi` (delivered to the plugin) and `forwardedMidi`. After `processBlock`, the output is rebuilt as `forwardedMidi + tempMidi` (`:278-280`). If the wrapped plugin does NOT consume the broadcast (i.e., leaves it in its MIDI buffer), the message appears twice downstream — once from `forwardedMidi`, once from the plugin's `tempMidi` output.

The regression test masks this: `MidiRoutingProbePlugin` defaults `clearInputDuringProcess = true` (`tests/rt_hosting_sprint_test.cpp:88`), so `tempMidi` is always emptied before the merge. The realistic "plugin passes MIDI through unchanged" path is never exercised for safety broadcasts (or for matching-channel events).

Severity is bounded because the three broadcast types are idempotent — a doubled All-Notes-Off has the same audible effect as one. But it is a real behavioral wrinkle and an untested code path. Recommend a test case with `clearInputDuringProcess = false` asserting the downstream buffer contains exactly one copy of each broadcast (which would currently fail and force a dedup decision), or an explicit note in the contract that duplicate idempotent broadcasts are acceptable-by-design.

### Minor

**1. Per-block heap allocation grows by one `MidiBuffer`.** `forwardedMidi` (`:210`) is a second per-block `MidiBuffer` whose `addEvent` can allocate on the audio thread. This is consistent with the pre-existing `tempMidi` pattern and is explicitly acknowledged in `docs/host-midi-routing-contract.md` ("Realtime Constraints"). Noted only so it isn't lost when the FIFO/preallocation hardening item on the plan is tackled.

**2. `addMidiMessage` (OSC path) does not grant the safety-broadcast exemption.** `:328` still uses the plain `(midiChannel == 0) || (message.getChannel() == midiChannel)` test, so an OSC-injected panic on a nonmatching channel is dropped. This is defensible (OSC injection targets one specific wrapped plugin and is documented as not graph-routed), but the asymmetry with the new `shouldDeliverMidiToPlugin` helper is worth a one-line comment so a future reader doesn't "fix" it into inconsistency.
